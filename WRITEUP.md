## Preliminary analysis of case

`case_files` contains four files:

* `ALongWayFromHome.7z`, a password-protected 7-Zip file (hash can be extracted with John the Ripper's `7z2john.pl` script);
* `capture_20260414_082412.pcap`, a PCAP dump of WLAN traffic (can be analyzed with WireShark);
* `mimikatz_dump.txt`, a Mimikatz-generated dump of Windows system credentials (NTLM hash is plainly readable from the dump); and
* `toonvault_encrypted.db`, an encrypted file, presumed to be a database protected by e.g. SQLCipher.

`case_information` contains the typical assignment files (analysis request detailing the case, and a profile sheet providing known information about the suspect). Also contained is a folder with 100 screenshots from the suspect's social media profiles, giving possible hints about the suspect's activities and interests.

The profile data makes it obvious that the suspect is deeply interested in comics and animation. The first steps are to analyze the suspect's former passwords for patterns and collect possible password components by scraping the internet for names and phrases related to the suspect's interests (Transformers, Teenage Mutant Ninja Turtles, Belgian and French cartoons etc.)

## Collecting wordlists

We implement some scrapers using the Python library `scrapy` and collect proper names (characters, episodes, creators...) related to the suspect's interests from Wikipedia, Fandom and other relevant sites.

## 00 - NTLM hash [done]

This is computationally the easiest of the four to crack. We start cracking it with a large extant list while we're building a custom password list, and we succeed in just minutes with the password `Cowabunga87`. For now we don't have a further use for this password -- maybe it's just a warmup...

## 01 - PCAP [done]

The PCAP file contains WLAN traffic within a network called "mywifi". The outermost layer is parseable in WireShark, but the data itself is encrypted. The `hcxtools` suite gives us some tools to start digging deeper. `hcxpcapngtool`, when pointed at the PCAP file, gives us a hash that can then be cracked with Hashcat. At this point we are armed with a wordlist containing, among other things, names of Asterix characters, and a simple wordlist attack hits the bullseye with the password `Fulliautomatix`.

Plugging the password into WireShark settings the traffic is encrypted and we are able to see a number of HTTP GET requests being made. WireShark allows us to simply export out the files. In total four files are extractable from this exchange:

* `readme.txt`, a short text file informing us that we are dealing with an internal file server;
* `sha256sums.txt`, SHA256 checksums for the three other files;
* `artifacts.zip`, a plain (unencrypted) ZIP file; and
* `themysterymachine.rar`, an encrypted RAR file.

After exporting all the SHA256 sums match. We can extract the unencrypted `artifacts.zip` without issues and we face a new layer of encrypted data. The RAR is encrypted with a password, so we use JtR's `rar2john` script to extract out the hash.

## 02 - 7Zip [done]

Hashcat mode -m 11600

The filename `ALongWayFromHome.7z` is a strong hint that the password has something to do with Lucky Luke's theme song and its lyrics. After creating a list from phrases in the song lyrics the 7-Zip cracks easily: the password is `PoorLonesomeCowboy`.

## 03 - ToonVault

The theme here could be anything related to cartoons.

If this is SQLCipher, hashcat mode -m 24600

Indeed, the database is locked with SQLCipher v4. After a lot of manual wordlist construction we finally hit the correct password: `TurtleTuesday!`. The database turns out to be a SQLite DB containing web forum data in two tables: `users` and `posts`, with 13 and 100 entries respectively. The `users` table has a column with the user password hashes; they are all sha512crypt (hashcat mode 1800).

Running `rockyou.txt` against the hashes cracks us 99 out of the 100 hashes. The only password not cracked by RockYou belongs, unsurprisingly, to `CowabungaDude87`.

One hash remains uncracked.


## 04 - Artifacts.zip [done]

This ZIP contains an encrypted data folder seemingly generated by a file synchronization utility called Syncthing. The three files are:

* `syncthing-folder-fb2e42.txt`, a plaintext file functioning as a Syncthing folder marker;
* `syncthing-encryption_password_token`, a small JSON file containing the folder's password token; and
* `R1/3JRAVGRK5HNOOI34712QGIB9V8UCMB5IV9CO`, the encrypted data blob itself.

The encryption scheme and workings of Syncthing are well documented. We are able to use the password token as something to bruteforce candidates against. Building a simple cracking script in Python (`crack_token.py`) and feeding it our scraped character list quickly reveals us the password: `Geriatrix`.

## 05 - RAR [done]

The filename `themysterymachine.rar` points to Scooby Doo so the password is presumably something related to that theme.

Hashcat mode -m 13000

After a long run of unsuccessful attemps the password turns out to be `mysteryinc.1987`. The RAR contains two files:

* `How_To_Get_Rich.pdf`, an encrypted PDF file; and
* `my_crypto.mv.db`, an encrypted H2 database.

## 06 - A Long Way From Home [done]

The 7z archive contains three files:

* `BlakeRanch.hc`, presumably a VeraCrypt container;
* `DaltonChat.docx`, a password-protected Office document; and
* `DaltonStash.hc`, presumably another VeraCrypt container.

John the Ripper extracts the hash from the docx file and the wordlist we have cracks it in seconds: the password is `JoeDalton`.

The document contains a chat log between the Dalton brothers giving hints about the encryption schemes of the two VeraCrypt stashes. To summarize:

* `BlakeRanch.hc` is protected by "second-generation" encryption that "the Blake family would appreciate", so it's probably BLAKE2.
* Averell reacts to this by talking about Lucky Luke's horse, so "Jolly Jumper" may well be a password component.
* `DaltonStash.hc` is "triple-locked" and "sealed under noble gas", likely meaning it uses three nested algorithms and Argon2 as the KDF.
* "Named after someone who was supposed to keep us in, but couldn't guard a sandwich." and "There's a picture of that stupid dog inside." probably refer to Rantanplan, which might be a password component.
* "These locks aren't your regular store-bought kind. You'd need the latest tools, freshly built." likely means that we need a recent Hashcat LE build (which is required for Argon2 at least), or some other nonstandard build of Hashcat.
* Averell's last line "Even something very basic would do. That's always a capital idea!" might point to capital letters being necessary in the password.

Digging a bit deeper it turns out we need to build the most recent version of VeraCrypt to be able to use either of the new functions (BLAKE2 and Argon2). With the help of Claude Code we manage to construct a Hashcat kernel for the BLAKE2 KDF case and use it to run through a long list of candidates; the password for `BlakeRanch.hc` is exactly `Jolly Jumper`. The stash contains a single AI-generated image `Cursed Jumper.jpg`, which does live up to its name.

Strong intuitions guide us to try the most obvious password for the `DaltonStash.hc` using the newfangled VeraCrypt version and hey presto, the password is simply `Rantanplan`. We are rewarded with another image, `Rantanplan.png`.

Neither picture shows signs of steganography or other hidden information, so we consider this pathway fully investigated

## 07 - PDF [done]

`How_To_Get_Rich.pdf` is an encrypted PDF file. Extracting the hash line is trivial with John the Ripper's `pdf2john.pl` tool. However the hash line alone does not tell whether the PDF is of version 1.7 level 3 (Hashcat module 10600) or 1.7 level 8 (Hashcat module 10700). The speed difference between these two modes is absolutely massive.

Checking the file with `qpdf` and `exiftool` the question is quickly solved: the encryption is V5.6, which unfortunately means the newer version (level 8) and drastically slower cracking. -m 10700 it is. 

The PDF opens with the password `sc00byd002015`.

## 08 - DB

The file `my_crypto.mv.db` is a database created with H2 Database Engine. This is a lesser-known database format and it doesn't seem to have Hashcat support at all. We put Claude Code to work and let it build us a hash extraction script and a Hashcat module. After testing it on a self-created database we are pretty sure it's working alright and we can start brute-forcing the password. The encryption used is an extremely light one: 10 rounds of PBKDF2 into an AES cipher.

Our first brute-force hit is a surprisingly non-thematic password `E12DESIRE`. This fails to open the database, so in all likelihood it is a false positive. Checking the decrypted bitstream this becomes obvious: the data is just garbage after the four-byte oracle `H:2,`. We update the oracle to check 8 bytes instead of 4 to dramatically decrease the less of coincidential matches.
